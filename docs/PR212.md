# PR #212 receiver cleanup

C5VRX by Twotoz and the C5VRX contributors.
[PR #212](https://github.com/Twotoz/C5VRX/pull/212) extends the C5VRX-5
hardware RF-to-CVBS path. This summary replaces the 25 PR-specific working
documents; their experiments and transcripts remain in Git history at
`01b0b9cda948434eba8ad70e40adf79468fd70a5`. Existing research data remains in
`research/data/`. No measured RF range gain is claimed.

## Current behavior

- Direct Gain V6 retains the last healthy gain across tracking resets on the
  same channel/filter/lane/scale/table, including AFC-offset changes. After a
  10-ms fade hold it climbs eight indices per 3 ms; overload above the anchor
  returns in one write. Exact-context V5 gain-map provenance is retained;
  version-4 map cache is discarded without resetting other saved settings.
- GAIN, console `G`: AUTO (default), MAX or fixed G78..G24; not stored since 2026-10-20 (every boot starts AUTO).
  Fixed modes bypass the controller and resume after calibration/scan.
- FLYWHEEL, console `U` (removed 2026-10-25: extreme desyncs and poor range; see FINDINGS.md): saved ON/OFF, default ON without a valid setting (OFF until 2026-10-18).
  Saved ON restores at boot. The native observer/comparator and gated output
  remain experimental: per-tip H/V trust and camera-level checks gate repairs;
  untrusted tips stay untouched. Monitor lock and useful weak-camera recovery
  are not established. IRQ-blackout pulse losses remain unresolved.
- Menu entry holds flywheel restarts and checks observer/output release
  before allocation. Word-aligned 384-byte internal DMA descriptor chunks
  need about 18 KiB NTSC / 22 KiB PAL for interlaced output; an allocation
  failure retries a progressive field at about 9 / 11 KiB. Refusal preserves
  live video. Menu transitions include a 150-ms relock gap. Reserve the
  6144-byte control stack before RF/driver allocations.
- OUTPUT, console `g`: 0.5x..5.0x in 0.5x steps, 1x default. Persist only
  after verified application; restore at boot. Scaling changes DAC6 bits
  only; higher levels can clip. Automatic OUTPUT remains research.
- AFC recovery retains brief missing-window history, accepts qualified B/W
  line timing and guards corrections with fresh evidence. Observer batches
  yield; cheap gain probes retain their cadence while full envelope work is
  paced and context/age checked.
- Physical RX tails, copy freshness and stream/PHY/gain ownership are checked.
  Live-carrier DC trials require fresh improvement or restoration. Disruptive
  live sampling scans are removed; monitoring remains passive.

## Evidence and limits

`test/test_sync_restart_runtime.py` now extracts `sync_live_context_t`, matching
the production rename. The firmware workflow runs host/runtime regressions,
research checks, the pinned ESP-IDF 6.0.2 build and linked-ELF IRAM audit.
[Exact-head CI](https://github.com/Twotoz/C5VRX/pull/212/checks) is the validation
record; a test/build result is not a board result.

Earlier board runs exposed heap fragmentation/menu allocation failures,
camera/flywheel drift, delayed/missed output pulses and a flash-resident ISR
helper during NVS writes. The source includes bounded callbacks,
per-tip H/V authority, checked menu release and a linked IRAM audit. Those
changes do not establish final-build display acceptance. Previous good boots
or model pass counts must not be attributed to the cleaned image.

The private-pulse preparation experiment failed its live latency gate.
Native H/V acquisition, controlled attenuation A/B/A, per-context residual DC,
CVBS levels under a 75-ohm load and affected-monitor lock remain separate
physical acceptance work. Live raw-ring sync repair is not enabled.
Issues [#201](https://github.com/Twotoz/C5VRX/issues/201) and
[#213](https://github.com/Twotoz/C5VRX/issues/213) remain open.

## Before merging

- Require successful firmware and web checks on the final PR head.
- Flash the artifact whose COMMIT matches that head; record its SHA256.
- Verify boot, responsive status/USB, GAIN persistence and zero transport faults.
- Open/exit NTSC and PAL menus with flywheel OFF and ON; verify the picture,
  heap behavior and clean return to live output.
- Toggle flywheel ON/OFF, reboot to check saved state, then leave it OFF.
  Record actual monitor behavior separately from software counters.

Final cleaned-build board validation is pending. See
[FIELD_TEST](FIELD_TEST.md) for the broader RF comparison protocol.

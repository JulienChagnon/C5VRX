# U80P64-R1: repair of the PR #250 model

This work is stacked on [PR #248](https://github.com/Twotoz/C5VRX/pull/248).
It extends [PR #250](https://github.com/Twotoz/C5VRX/pull/250), source commit
`9e4a6163e6cfde5620137d70097cf91344e24c68`. The original P64 parameters,
LUT builder and scoring tools are C5VRX work by Twotoz and the contributors.
The original champion remains reproducible with SHA-256
`cb4bd6ef835b21ed32aeb6fd9242109f348ba81f0cda869cfd5e0cf796e41b2f`.

The public name is **U80P64-R1**: an untrained closed-form tracker, video
loop gain 0.80, 64 phase states, revision 1. Untrained means no fitted LUT
entries; parameter exploration and simulation validation are still recorded.
The same table was first flashed and tested under the temporary name P64-R1.

## Controls and exact identity

U85Q remains the boot default. Console `m` explicitly selects **U80P64-R1** for
one session, through the existing bounded, verified restart and shared
five-second cooldown. Menu selection applies at exit. A reboot returns to
U85Q. P64 uses one fixed table; `K/k/j` cannot overwrite it. The retired
LP controls `P`/`O` and live LUT-write bench `H` are no longer compiled. OUTPUT,
flywheel comparator format and analog profiles retain their normal ownership,
verification and rollback. Profile changes still use the guarded restart.

`T` reports `DEMOD selected=... verified=... p64_model=U80P64-R1` and the
compiled table SHA-256. The selected program is not reported as verified
when transport state is unknown or faulted. `program=U80P64-R1` distinguishes
this repair from the original model and the U85Q reference.

## Reproducible defects and correction

The original table can emit constant DAC code 15 for a clean -1 MHz porch
or 0 MHz tone at IQ radii 2..6 cells; the physical transfer requires about
21 or 25.2. Its sync-exit threshold and negative prior can retain a sync
state, while the sync ceiling masks the incorrect prediction. All 64 states
being reachable did not test this behavior.

U80P64-R1:

- Uses all 16 tokens for phase observations instead of 12 phase sectors plus
  four erasure tokens. Their spacing is 22.5 degrees; weak IQ is not labelled
  as a permanently low-confidence token that cannot leave the sync corridor.
- Lowers the coarse-to-fine exit threshold to allow the porch to escape.
- Derives recovered frequency from the **committed quantized phase advance**,
  rather than the predicted advance before state quantization. It removes
  the forced sync/video DAC clamps and arbitrary code offset from this path.
- Retains 14 coarse negative-frequency phase states and 50 fine states:
  the fine-state grid is 7.2 degrees, not measured input phase accuracy.

The layout stays 1024 LUT16 words: DAC bits 0..5, next state 6..11, token
12..15. MODEM_DIAG -> RX40 -> raw 32 KiB ring -> two TX BitScrambler lookups
per pair -> unique CVBS20 duplicated as [D,D] at TX40. No CPU sample loop.
The program embeds the complete LUT; the original `lut 0` loader defect,
program/table pairing, comparator format and verified rollback fixes remain.

## Host evidence and limits

`test/test_p64.py` rejects the original porch regression, checks 588 clean
tones across -5.5..+6.5 MHz, three IQ radii and four start phases, and checks
sync-to-porch escape. The worst mean transfer error is below 0.5 DAC code.
It also checks the full loader image and ESP-IDF-assembled instructions
against an independent pair/state reference. Runtime tests execute the
production restart, format, OUTPUT, cooldown and rollback paths.

`research/p64_model.py` reproduces both the original and repaired models;
parameters are in `research/data/p64_repair.json`. Run
`python research/p64_validation.py --check` to reproduce the 12 PAL/NTSC
cases in `research/data/p64_repair_validation.json`. Seed 311 was used for
candidate exploration, 991 for preliminary comparison, and 2903 for final
validation after fixing the parameters. These are synthetic ADC/goggle
models. They do not prove physical picture, chroma, timing or range gains.
There are weak-signal noise versus line-lock tradeoffs; no universal
improvement over U85Q is claimed.

## Hardware evidence correction and next check

The initial COM10/A1 comparison on 2026-10-23 had the **VTX off**, as the
operator subsequently clarified. It was not a valid picture-quality A/B and
does not establish a P64 failure with a live carrier. A later VTX-on capture
returned no valid IQ data. A later explicitly confirmed VTX-on check on build `d894bef` succeeded:
status reported `selected=P64-R1 verified=P64-R1`, the expected table SHA-256,
NTSC detection and AFC lock. The operator reported good video. An 8190-byte
IQ capture (204.75 us) passed its checksum, with no rail samples. DMA,
overflow, BitScrambler-overload and program/LUT verification counters were zero.
This is one positive NTSC observation, not PAL, range or weak-signal acceptance.
Flywheel repair was not established (`acquired=0` in that snapshot). The VTX
was told to be turned off immediately after capture. This name change leaves
the tested table unchanged; that build still reports the old name until reflashed.

The operator controls VTX power: it stays off until an explicit confirmation
that it is on. Announce short measurement windows and tell the operator to
switch it off immediately afterwards. Restore USB status before asking for
RF power. A valid test must confirm the exact firmware and verified model,
then capture the same live input for U85Q and U80P64-R1. Check NTSC/PAL picture,
colour/detail, sync, VTX recovery and transport counters. Host tests alone
must never make P64 the boot default.

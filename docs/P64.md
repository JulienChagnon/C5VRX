# P64 on digital RX mode 0

This change is stacked on [PR #248](https://github.com/Twotoz/C5VRX/pull/248)
and imports the P64 model from [PR #250](https://github.com/Twotoz/C5VRX/pull/250),
commit `9e4a6163e6cfde5620137d70097cf91344e24c68`.
P64 and its champion parameters are C5VRX work by Twotoz and the contributors.
The earlier U85Q and shared-word investigations remain the foundation; see
`legacy/c5vrx4/RESEARCH.md` and `research/u85q_lp.py`.

## Model and controls

P64 is the boot default for this branch. Console `m` selects P64 or U85Q
for the session. A live selection uses the existing bounded, verified restart
and shared five-second cooldown. It briefly interrupts video. Selection from
the menu is staged until menu exit. Boot always returns to P64.

The imported champion has 14 sync states and 50 video states. The video-state
grid is `360 / 50 = 7.2` degrees. This is not a measurement of phase accuracy:
ordinary observations still have 12 phase sectors (30 degrees), four weak-IQ
tokens, and folded Q4/I4 input. Its shared LUT word packs DAC6 at bits 0..5,
next state at 6..11, and token at 12..15. All 64 states are reachable.

The realtime path remains MODEM_DIAG -> PARLIO RX40 -> raw 32 KiB ring ->
TX BitScrambler -> DAC. Two lookups per IQ pair produce unique CVBS20,
duplicated as `[D,D]` at physical TX40. The CPU does not process samples.

P64 uses one fixed 1024-word table. U85Q's kp/LP ladder and live LUT bench
(`K/k/j/P/H`) cannot rewrite it. Analog profile/filter changes still work;
their starting kp level is retained for a later U85Q selection. OUTPUT scales
only DAC bits. The flywheel comparator format uses P64's own instruction
program and state packing, including during OUTPUT changes and rollback.

## Integration fixes relative to PR #250

- Embed the complete champion LUT in `u85q_64.bsasm`. Its original `lut 0`
  assembled to a one-word LUT, rejected by production `program_words()`.
- Select the program and canonical table together on boot, menu exit,
  OUTPUT changes and comparator-format changes. U85Q-LP instructions cannot
  interpret P64's six state bits / four token bits.
- Restore the verified demodulator identity before rebuilding the rollback
  program; publish the new identity only after successful transport restart.

`research/p64_model.py` adapts the LUT builder from #250 without its search
or benchmark dependencies. It reproduces the imported table, preserving all
champion words. `test/test_p64.py` checks parameters, reachability, clamps,
full loader binary layout and the assembled program against an independent
pair/state reference. Runtime tests execute production selection, publication,
OUTPUT, format and rollback code with mocked SDK boundaries.

## Evidence and board checks

The champion JSON contains optimizer simulation scores on its search cases.
They are not physical measurements or held-out performance guarantees.
This combined mode-0/P64 firmware has no hardware, goggle-lock or range proof.
Neither 7.2-degree state spacing nor a noise-only filter difference establishes
better RF sensitivity or additional range.

Before accepting the build on hardware: check `T` reports `program=P64` and
`DFILT want=0 hw_mode=0`; confirm PAL and NTSC colour, luma/detail, sync and
VTX-off/on recovery. Exercise `m` in both directions with cooldown, menu
entry/exit, all required OUTPUT levels, flywheel on/off, profile changes,
channel changes across 5830 MHz and AFC. Watch verification/restart failures,
`tx_empty` and `bs_overload`; measure actual picture and reception separately.
